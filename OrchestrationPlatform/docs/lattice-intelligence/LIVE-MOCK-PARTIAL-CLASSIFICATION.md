# Live, Mock and Partial Classification

## Classification register

### Source-authoritative when connected
- Teamcenter exact-ID item/revision/BOM extraction.
- Windchill part/structure extraction.
- SAP material/BOM and captured operational records.
- Configit package/solve/normalized structure.
- Source-native artifacts captured with provenance/checksums.

### Backend-derived
- Standard status normalization.
- Federated discovery/extraction aggregation.
- Candidate evaluation and unified identity assessment.
- Typed source evidence mapping.
- Evidence completeness.
- Engineering findings generated by backend evaluators.
- Retry/cancellation/job state.

### Frontend-derived
- Current cross-BOM impact matching and affected occurrence rollup.
- Current loaded-BOM comparison and comparison reasoning.
- Current requirement-to-part association.
- Windchill revision difference presentation/calculation where based on loaded trees.
- Current Lattice graph assembly from `LatticeHandoff`.

### Hardcoded
- Requirement catalog in `hardcoded-part-requirements.json`.
- Any demonstrations that depend on that catalog.

### Mocked
- Test fixtures under Lattice tests and other explicit fixture/sample assets.
- No production capability should inherit this label merely because test fixtures exist.

### Partially implemented
- Teamcenter product-name discovery and revision-rule fidelity.
- Durable Teamcenter occurrence UID.
- Teamcenter datasets/related-object completeness.
- Windchill change notice/task connected completeness.
- SAP operational breadth across authorization/configuration variants.
- Configit feature/rule/constraint preservation and explainability.
- Direct Lattice consumption of backend unified intelligence.

### Unavailable
- Authoritative requirements-system connector.
- Backend canonical requirement intelligence endpoint.
- Backend canonical cross-BOM impact endpoint used by current part-click flow.
- Final versioned engineering-intelligence graph endpoint for Lattice.

## Critical interpretation
“Implemented” is not equivalent to “connected and proven.” Source-authoritative classification applies only to data actually returned by a successful, authenticated connector run with provenance. In disconnected demonstrations, the correct runtime state is partial or unavailable.

## Classification legend
- **source-authoritative**: returned from a source connector or source-owned artifact, subject to provenance and freshness checks.
- **backend-derived**: calculated in the .NET orchestration/intelligence layer from source results.
- **frontend-derived**: calculated in browser-side libraries or stores.
- **hardcoded**: supplied from repository static data rather than a connected system.
- **mocked**: intentionally simulated behavior or fixture data.
- **partially implemented**: code path exists but available evidence does not prove complete connected behavior.
- **unavailable**: current code explicitly reports capability absence or no implementation was found.

This audit is a static source audit of `platform-full-repo-audit-bundle.txt`, generated 2026-09-01. It distinguishes implementation evidence from connected-system proof. No live Teamcenter, Windchill, SAP, or Configit call was executed in this sprint.
