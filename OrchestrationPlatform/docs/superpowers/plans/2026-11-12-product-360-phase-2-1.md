# Product 360 Phase 2.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add evidence-rich, cited application digests to Product 360 and isolate broad single-application overviews to the requested application.

**Architecture:** Extend the existing classifier with a narrow `application-overview` intent, while preserving all current focused-intent precedence. Build bounded application digests from canonical investigation entities and selected governed relationships, retain their source citations in the existing allowlist, and replace redundant Product 360-only prompt/context projections rather than appending evidence.

**Tech Stack:** TypeScript, Vitest, ESLint, existing Lattice Copilot context builder, citation validation, mocked executor/persistence.

**Spec:** `docs/superpowers/specs/2026-11-12-product-360-phase-2-1-design.md`

## Global Constraints

- “No changes to representative selection, ontology resolution, impact reasoning, source extraction, RAG, embeddings, persistence schema, or UI selection.”
- “No live provider requests, context-limit increase, commit, or push.”
- “Do not infer cross-application relationships from shared-subject participation.”
- “Do not infer operational consequences, completeness, causality, or conflicting values.”
- “Do not copy complete child-entity payloads into a model-facing projection.”
- “Do not use extraction order, record count alone, or generic retrieval scores as fact-selection criteria.”
- Keep the configured Product 360 and application-overview context limit at 24,000 characters.
- Preserve M1, E1, M2, focused intents, citation validation, persistence, rendering, and source-state caveats.
- Use mocked provider and persistence behavior only.
- Do not commit or push.

## Review Focus

- A broad application question must not steal a focused requirement, material, family, document, relationship, impact, risk, change, or root-cause question; test focused-intent precedence in `document-intent.test.ts`.
- A recognized but nonparticipating application must not receive another application's facts or global coverage; test an absent application in `context-builder.test.ts` and mocked persistence.
- Sparse or stale evidence must yield fewer digest facts rather than fabricated or uncited content; test the saved fixture's partial/stale state and a sparse fixture in `context-builder.test.ts`.
- Hierarchical secondary records must remain internal to their application and must not imply a cross-system link or consequence; test Configit hierarchy and Windchill/SAP boundaries in `context-builder.test.ts` and traceability regressions.
- Budget compaction must preserve subject, representatives, citations, digest facts, evidence boundaries, and verified relationships before secondary names/categories; test both 24,000-character limits and retained fields in `context-builder.test.ts`.

- If an application-overview scope is recognized but has no participation group, return no digest for it and retain the requested application scope so the prompt and answer coverage can explicitly state that no such application evidence is present.
